# 3000 每日数据库备份减负

仅备份 `newapi-mysql/defaultdb`：业务表数据完整保留，`logs` 和自动过期的
`error_request_traces` 只保留表结构、索引和触发器。现网数据不修改，数据库不重启。

MySQL 8.0 客户端没有 `--ignore-table-data`，因此先用单事务导出其余表的全部数据，
再追加这两张表的 `--no-data` 导出。业务表仍在同一事务快照中。
原每日 20:30 cron、备份文件命名、7 日本地保留和 R2 上传位置保持不变。

导出复用 `audit-backup` 的精确 PID/启动时间/连接属性清理逻辑；只终止自身查询。
每秒检查自己的服务器连接，单条执行超过 120 秒、等锁超过 5 秒即在服务端取消；
每段导出总期限 900 秒。失败不会发布不完整备份。
新入口与其他数据库备份共用锁，最多等候 300 秒。

凭据在原容器内使用既有变量，不进入源码、命令参数或输出；原含密码脚本保存在
仅 root 可读的回滚目录。安装要求原脚本 SHA 完全匹配、容器凭据相同，
并要求已核验 CI 产物的精确提交号。共用清理模块也逐字节核对后才安装。

安装先运行 `python3 install.py` 预览，再使用本轮核验提交号设置
`NEWAPI_DB_BACKUP_CONFIRM_COMMIT`，执行 `python3 install.py --apply`。
安装不改 cron，不部署 NewAPI/Monitor，不启用全局维护。

验收必须生成一份真实备份，在无网络、无发布端口、有限 CPU/内存的新 MySQL
容器恢复；核对全部表及两张空表、核心业务行数和诊断表结构/索引。
不得恢复进生产数据库。备份仅有归档格式检查不算恢复成功。

若需回滚，停止本轮备份任务后，在共用备份锁内将
`/opt/newapi-db-backup-rollback/original.sh` 原子恢复到原入口，权限 700；
不删除备份、不重启任何生产服务。
